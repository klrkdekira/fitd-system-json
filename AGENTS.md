# Blades in the Dark SRD System JSON

## Project purpose

This repository turns the local `Blades-in-the-Dark-SRD.md` into a modular Blades in the Dark SRD reference corpus using JSON-LD 1.1 and JSON Schema Draft 2020-12. `SPECIFICATION.md` is the source of truth for architecture, scope, extraction rules, and acceptance criteria. The architecture adopts graph20 (https://cheeleong.dev/graph20/).

## Source discipline

- Treat `Blades-in-the-Dark-SRD.md` as the authoritative in-scope source. It is CC-BY-3.0: the attribution statement must survive in the source record, manifest, README, and llms-full output, together with the conversion statement crediting the upstream Markdown conversion.
- Do not add material from the full rulebook, wikis, or other Forged in the Dark games without a separate source record and rights metadata.
- Preserve source wording in `rulesText`/`examplesText`/`commentary`; structured fields are indexes, not replacements.
- Never silently repair conversion anomalies in parser code, and never edit the source file. Every normalisation goes through `objects/sources/extraction-overrides.json` with observed text, treatment, rationale, and status; the extractor verifies the observed text before honouring an entry.
- Never invent missing values.

## Data conventions

- JSON-LD 1.1; JSON Schema Draft 2020-12; base IRI `https://cheeleong.dev/fitd-system-json/`.
- Use `@id` node references for semantic links; `$ref` only for schema composition. Predicates declared `@type: "@id"` must never be emitted as bare strings.
- Properties camelCase; slugs and filenames lowercase kebab-case; classes PascalCase.
- Everything under `objects/` (except `extraction-overrides.json`) is generated by `scripts/`; never hand-edit generated files.

## Change workflow

1. Change scripts/schemas, then rebuild: `make extract manifest bundle llms-full search-index collection-index`.
2. Verify with `make test validate schema fidelity graph`, and `make determinism` before finishing (`make check` runs everything).
3. Keep generated output deterministic: no timestamps, no randomness, sorted listings.
4. Do not implement a rules engine, character builder, or campaign state in this corpus.
